Detailed Description

template<typename T>
class tividy::WorkItemDecorator< T >

Decorator of the Decorator pattern: wraps another WorkComponent and forwards everything to it.

Concrete decorators override only what they add. The decorator owns the wrapped component (inner). Queries that identify the component (find, getItems, iteration) report the outermost decorator so commands always run through every layer; parent and mediator are forwarded to the innermost WorkItem, which is the real colleague of the Mediator. The WorkflowBuilder always wraps in this order: AuditedWork( EscalatedWork( ApprovedWork( WorkItem ) ) ).

int  numAssignees = -1 
) const
overridevirtual

Selects assignees without changing anything (Strategy pattern).

The candidates are the given pool; each strategy filters the result of the previous one in list order; then numAssignees are chosen (the first ones, or random ones if a RuleAssignment is present). Pass -1 to select everyone left.

Exceptions
InvalidAssignmentArgumentExceptionfor invalid arguments.
InsufficientParticipantsExceptionif too few candidates remain.
